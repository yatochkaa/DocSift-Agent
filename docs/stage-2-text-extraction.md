# Этап 2. Извлечение текста

## Единый контракт

`TextExtractionService.extract(path)` возвращает `TextExtractionResult`:

- страницы исходного документа;
- текстовые блоки с нормализованными координатами `0..1`;
- найденные таблицы;
- общий и постраничный признаки `used_ocr`;
- исходные размеры страницы для отладки и последующего отображения.

Нормализованные координаты не зависят от DPI, PDF points или размера фотографии.
Excel и CSV представлены как страницы-листы, а координаты ячеек нормализованы по
числу строк и столбцов.

## Стратегии

- PDF с пригодным текстовым слоем: PyMuPDF извлекает блоки и таблицы напрямую.
- PDF без пригодного слоя: страница рендерится в 300 DPI, проходит предобработку и OCR.
- Изображения: EXIF-поворот, grayscale, autocontrast, бинаризация Otsu, deskew, затем OCR.
- XLSX/XLS: `openpyxl`/`xlrd`, без OCR и LLM.
- CSV: стандартный модуль `csv`, попытка UTF-8 BOM и CP1251, без OCR и LLM.

## Эвристика текстового слоя PDF

Проверка выполняется для каждой страницы отдельно, поэтому смешанный PDF может использовать
обычный текст на одних страницах и OCR на других.

Текстовый слой считается пригодным, если одновременно:

1. найдено не меньше 50 букв или цифр;
2. найдено не меньше 10 слов;
3. не меньше 80% непробельных символов являются печатными и не равны символу замены `�`.

Порог 50 символов отсекает номера страниц, водяные знаки и единичные подписи, которые часто
ошибочно принимаются за полный текстовый слой. В типовом счёте или акте находятся сотни
символов. Порог в 10 слов дополнительно защищает от длинных технических идентификаторов.
Порог качества 80% ловит PDF с повреждённой кодировкой встроенного шрифта. Для редких очень
коротких документов ложный переход на OCR безопаснее, чем потеря содержимого.

## Выбор OCR для русского языка

| Критерий | Tesseract 5 (`rus+eng`) | PaddleOCR |
|---|---|---|
| Печатный русский скан | Хорошая точность после предобработки | Обычно хорошая или выше |
| Фото с шумом, наклоном и сложной вёрсткой | Средняя точность | Обычно лучше Tesseract |
| CPU и старт | Лёгкий, быстрый старт | Тяжелее и медленнее на CPU |
| Размер | Небольшой движок и языковые данные | Крупные Python-зависимости и модели |
| Docker на Windows | Один `apt-get`, предсказуемо | Сложнее сборка, модели и совместимость wheels |
| Приватность | Полностью локально | Полностью локально |

Для первого production-каркаса выбран **Tesseract 5**. Он бесплатный, локальный, поддерживает
русский языковым пакетом Debian и заметно проще для одного разработчика на Windows + Docker.
Предобработка компенсирует часть разницы на фотографиях. OCR скрыт за `OcrEngineProtocol`,
поэтому PaddleOCR можно подключить позже без изменения PDF, image и spreadsheet extractors.

На этом этапе OCR возвращает текстовые блоки, а список таблиц может быть пустым. Надёжное
восстановление структуры таблиц из сканов требует отдельной модели layout analysis и не должно
имитироваться эвристикой. Таблицы из текстовых PDF, Excel и CSV извлекаются напрямую.

## Тестовая стратегия

Тесты создают три валидных файла на диске: PDF с текстовым слоем, PDF с растровой страницей и
фотографию. Проверяется выбор правильной ветки, непустой результат и форма контракта, а не
качество распознавания. OCR подменяется детерминированным адаптером, чтобы unit-тесты не
зависели от установленного на хосте Tesseract; production-контейнер содержит Tesseract и
`rus+eng`.
